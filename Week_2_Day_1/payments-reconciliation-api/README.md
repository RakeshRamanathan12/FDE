# Invoice and Payments Reconciliation API

A beginner-friendly FastAPI project for invoice data-quality checks and a JSON-backed Payments CRUD API.

## Features
- Normalize vendors with `strip().title()` and statuses with `strip().upper()`.
- Report null-amount rows by zero-based original index and exclude them from totals.
- Detect exact duplicates and keep the first copy.
- Report suspected duplicate pairs without removing them.
- Match negative credit notes to earlier positive invoices for the same normalized vendor and equal absolute amount.
- Sum payments by `invoice_id` and identify payments with no matching invoice.
- Payments API: GET, POST, PUT, PATCH, DELETE.
- JSON persistence, Swagger UI, and basic tests.

## Run locally
Python 3.10+ recommended.

```bash
python -m venv .venv
```

Windows:
```bash
.venv\Scripts\activate
```

macOS/Linux:
```bash
source .venv/bin/activate
```

Install and run:
```bash
pip install -r requirements.txt
uvicorn main:app --reload --port 8002
```

Open Swagger UI at http://127.0.0.1:8002/docs.

## Endpoints
| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/` | Health check |
| GET | `/invoices/` | List invoices |
| GET | `/invoices/{invoice_id}` | Get invoice by ID |
| GET | `/invoices/reconciliation` | Run reconciliation |
| GET | `/payments/` | List payments |
| GET | `/payments/{payment_id}` | Get payment by generated payment ID |
| POST | `/payments/` | Create payment |
| PUT | `/payments/{payment_id}` | Replace a payment |
| PATCH | `/payments/{payment_id}` | Partially update a payment |
| DELETE | `/payments/{payment_id}` | Delete a payment |

## Example POST `/payments/`
```json
{
  "invoice_id": "INV-102",
  "paid": 1200
}
```

Payment IDs are generated by the API and are separate from invoice IDs. PUT requires both fields; PATCH can update one field.

## Reconciliation assumptions
1. Vendor and status normalization occurs on a copy; source JSON is not modified.
2. Null-amount rows are reported and excluded from duplicate/credit/totals processing.
3. Exact duplicate detection compares all fields after normalization; the first row is retained.
4. Suspected duplicates share normalized vendor, amount, and date but have different invoice IDs. They are reported, not removed.
5. Credit notes pair with an earlier positive invoice for the same vendor and absolute amount; each row is paired at most once. Unmatched negative rows are reported.
6. Payments are summed by invoice ID; payments with unknown invoice IDs are reported as unmatched.
7. JSON is suitable for this homework, not for high-concurrency production use.
